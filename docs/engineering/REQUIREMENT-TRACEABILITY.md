# Requirement Classification & Traceability Matrix

This matrix unifies specifications across Phases 0–11 into stable requirement identifiers, reconciles duplicate/conflicting requirements, and binds every requirement to verified artifacts.

## Classification Taxonomy
- `CORE_REQUIREMENT` — Non-negotiable timebase, DSP correctness, immutability, and data integrity.
- `ASR_PIPELINE_REQUIREMENT` — Acoustic preprocessing, normalization, alignment, ensemble, and transcription contracts.
- `STREAMING_REQUIREMENT` — `ASR1` protocol, VAD hysteresis, partial/final stabilization, and latency SLAs.
- `ROUTER_REQUIREMENT` — Engine registry, 18-gate eligibility, cascade policy, budget & circuit breaker.
- `MODEL_TRAINING_REQUIREMENT` — Dataset split zero-leakage, checkpoints, SFT/LoRA, and Phase 7 GO/NO-GO gates.
- `SECURITY_COMPLIANCE_REQUIREMENT` — Tenant isolation, secret handling, upload/frame sanitization, privacy, SBOM.
- `CONTINUOUS_LEARNING_REQUIREMENT` — Consent gate, active learning, replay anti-forgetting, PSI drift, canary rollout.
- `PLATFORM_API_REQUIREMENT` — Multi-tenancy, RBAC, `/v1/*` APIs, idempotency, minor-unit billing ledger, SDKs, residency.
- `INTELLIGENCE_CAPABILITY` — Phase 11 diarization, forced alignment, subtitles, meeting intelligence, analytics, search.
- `DEFERRED_BY_DESIGN` — Explicitly held back by Phase 7 NO-GO / external hardware-budget prerequisites.
